# upd-parser

Парсер электронного **универсального передаточного документа (УПД)** в формате ФНС 5.03, написанный на C++20.

Программа читает XML-файл УПД, разбирает его в типизированную модель данных (шапка документа, продавец, покупатель, строки с товарами, итоги) и сообщает о проблемах в файле с указанием точного места в дереве XML.

## Что такое УПД

УПД — основной документ электронного документооборота (ЭДО) между компаниями в России. Он объединяет счёт-фактуру и документ об отгрузке товаров или оказании услуг. Формат файла — XML, его структуру утверждает ФНС: приказ от 19.12.2023 № ЕД-7-26/970@ (версия формата 5.03) с последующими изменениями.

Особенности формата, которые учитывает парсер:

- имена элементов и атрибутов на русском языке (`Файл`, `Документ`, `СвСчФакт`, `НомерДок`...);
- исходные файлы в кодировке **windows-1251**;
- элементы-«выборы»: участник сделки может быть организацией (`СвЮЛУч`) или индивидуальным предпринимателем (`СвИП`), а сумма налога задаётся числом (`СумНал`) или пометкой «без НДС» (`БезНДС`).

## Сборка

Требования:

- Linux (или WSL2 в Windows)
- компилятор с поддержкой C++20: GCC 11+ или Clang 14+
- CMake 3.24+
- git и доступ в интернет при первой сборке (CMake скачивает pugixml)

Установка инструментов в Ubuntu:

```bash
git clone https://github.com/Stref13/upd-parser.git
cd upd-parser
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
```

## Запуск

Запускать из корня репозитория:

```bash
./build/upd_parser
```

Сейчас программа читает учебный пример `samples/upd_example_utf8.xml`. Передача пути к файлу через аргумент командной строки — в планах.

## План развития

1. **Парсер УПД** (текущий этап): консольная утилита, разбор и базовая проверка документа.
2. **Хранение в PostgreSQL**: схема базы, сохранение документа в одной транзакции через libpqxx.
3. **Валидация**: проверка по XSD-схеме ФНС (libxml2), бизнес-проверки (суммы, контрольные числа ИНН, даты).
4. **HTTP API**: загрузка документов, получение статуса, поиск с фильтрами и постраничным выводом.
5. **Фоновая обработка**: очередь задач на RabbitMQ, жизненный цикл документа «получен → проверен → обработан».
6. **Нагрузочное тестирование**: генерация документов, профилирование, пул соединений, кэш на Redis.
